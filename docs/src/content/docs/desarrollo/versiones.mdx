Translay usa [versionado semántico](https://semver.org/lang/es/): `mayor.menor.parche`. La versión vive en `vt/__init__.py` (`python run.py --version`) y en `docs/package.json`; cada versión es una etiqueta `vX.Y.Z`.

| Sube | Cuando desde la última versión hay… |
|---|---|
| Mayor | un cambio incompatible (`!` o `BREAKING CHANGE:`): datos que hay que migrar, rutas de la API que cambian |
| Menor | al menos un `feat` |
| Parche | solo `fix` o `perf` |

## Liberar

<Steps>

1. Revisa que «Sin publicar» en `CHANGELOG.md` cuente todo lo que cambió, agrupado como en las versiones anteriores.

2. Consulta qué número toca según los commits:

   ```sh
   python scripts/release.py --next
   ```

3. Prueba y libera:

   ```sh
   python scripts/release.py 1.1.0 --dry-run
   python scripts/release.py 1.1.0
   ```

   Cambia la versión, mueve «Sin publicar» a `## 1.1.0 · <fecha>`, hace el commit `chore(release): v1.1.0` y la etiqueta anotada `v1.1.0` con las notas.

4. Publica:

   ```sh
   git push --follow-tags
   ```

   `.github/workflows/release.yml` crea la versión en [Releases](https://github.com/alenj0x1/translay/releases) con las notas del changelog al llegar la etiqueta.

</Steps>

## Repositorio

[github.com/alenj0x1/translay](https://github.com/alenj0x1/translay), rama `main`. Los commits van a nombre de `alenj0x1` con el correo privado de GitHub (`140274341+alenj0x1@users.noreply.github.com`), configurado en el repositorio:

```sh
git config user.name alenj0x1
git config user.email 140274341+alenj0x1@users.noreply.github.com
```

| Flujo | Cuándo | Qué hace |
|---|---|---|
| `docs.yml` | push a `main` con cambios en `docs/`, `vt/` o `CHANGELOG.md` | Compila y publica la documentación |
| `release.yml` | etiqueta `vX.Y.Z` | Crea la versión con las notas del changelog |
| `commits.yml` | pull request | Revisa que los commits sigan la convención |
