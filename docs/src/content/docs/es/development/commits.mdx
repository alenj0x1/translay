Los commits siguen [Conventional Commits 1.0](https://www.conventionalcommits.org/es/v1.0.0/), con la descripción en español. Así el historial se lee solo y la próxima versión se calcula a partir de él ([Versiones](../releases/)).

```
tipo(alcance): descripción en minúscula, sin punto final

Cuerpo opcional: qué cambia y por qué.

BREAKING CHANGE: qué deja de funcionar y cómo migrar
```

## Tipos

| Tipo | Para | Versión |
|---|---|---|
| `feat` | Algo nuevo que la persona puede usar | menor (1.**1**.0) |
| `fix` | Un error corregido | parche (1.0.**1**) |
| `perf` | Más rápido o con menos memoria, sin cambiar lo que hace | parche |
| `refactor` | Código reorganizado sin cambiar el comportamiento | — |
| `style` | Formato del código (no del diseño de la interfaz: eso es `feat` o `fix`) | — |
| `docs` | Solo documentación | — |
| `test` | Pruebas | — |
| `build` | Dependencias, Dockerfile, empaquetado | — |
| `ci` | Flujos de GitHub Actions | — |
| `chore` | Mantenimiento (incluye `chore(release)`) | — |
| `revert` | Deshace un commit anterior | — |

Un `!` antes de los dos puntos (`feat(api)!: …`) o un pie `BREAKING CHANGE:` marca un cambio incompatible: sube la versión mayor (**2**.0.0).

## Alcances

Opcionales, en minúscula y con tildes: el área de la app que cambia.

`biblioteca` · `bibliotecas` · `importar` · `cola` · `reproductor` · `voz` · `traducción` · `reconocimiento` · `exportar` · `acceso` · `api` · `webhooks` · `youtube` · `interfaz` · `docker` · `docs`

## Ejemplos

```
feat(cola): priorizar desde la tarjeta
fix(voz): las referencias ya no se recortan adivinando el texto
perf(reconocimiento): limitar el caché de CTranslate2 a 400 MB
docs(api): ejemplo de exportación con curl
build(docker): imagen con CUDA 12.8
feat(api)!: las rutas de videos pasan a /api/v2
```

## Validación

`.githooks/commit-msg` rechaza un mensaje que no siga el formato y un `feat`, `fix` o `perf` que cambie la app (`vt/`, `web/`, `Dockerfile`, `requirements.txt`…) sin tocar la documentación ni `CHANGELOG.md` (ver [Documentación](../docs/)). Se activa una vez por clon:

```sh
git config core.hooksPath .githooks
git config commit.template .gitmessage
```

La segunda línea deja una plantilla con los tipos y alcances al abrir el editor del commit.

<Aside>
Si un cambio de verdad no necesita documentación (un arreglo interno invisible), agrega `Docs: no aplica` como última línea del mensaje.
</Aside>
